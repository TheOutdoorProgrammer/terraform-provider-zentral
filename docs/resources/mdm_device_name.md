# zentral_mdm_device_name (Resource)

Manages the name of one exact enrollment, guarded by its serial number. Apply sends Apple's Settings/DeviceName command only when needed, checks both the command and setting acknowledgement, then independently queries DeviceName. Supervision is required for iPhone and iPad. Blocked and checked-out enrollments are rejected.

Planning and refresh never send commands. Read uses Zentral's cached inventory, or the provider's completed verification result if that is newer than the latest acknowledged native DeviceInformation query. Consequently, changes made on the device are only detected after Zentral receives a fresh observation. A custom DeviceInformation command does not update Zentral's native inventory name or its UI; the next native inventory query does that.

Destroy only stops managing the name. It does not reset the previous name, unenroll, cancel queued commands, or erase the device. Re-enrollment needs an explicitly updated enrollment ID. Do not manage one device from multiple resources or states.

## Requirements

The API token needs `mdm.view_enrolleddevice`, `mdm.add_devicecommand`, and `mdm.view_devicecommand`. Use environment variables for provider credentials.

The server must wake the device after a custom API command is committed for unattended operation. The accompanying Zentral change enables this for `SendCustomEnrolledDeviceCommand`. Older server versions queue the command but need a separate device check-in or manual Poke. Provider polling cannot wake a device through APNs.

## Incomplete operations

An offline device may return NotNow or miss the apply timeout. The resource retains command UUIDs after successful submission and resumes an interrupted update when the target name is unchanged. A previous pending rename must complete or be canceled in Zentral before a different name can be submitted.

An interrupted creation may be marked tainted by Terraform. Do not blindly retry or replace it: inspect the retained command IDs in Zentral first. A network failure after the server accepted a POST can also leave a command queued without its UUID being returned. The server has no idempotency key for this endpoint. Once the intended name is confirmed, import the exact enrollment to adopt it. Errors and timeouts never prove a command was canceled.

Names, serial numbers, enrollment IDs, and command UUIDs are kept in state. Protect state as personal data. This resource never takes a WireGuard private key or arbitrary command payload.

## Example Usage

```terraform
resource "zentral_mdm_device_name" "device" {
  serial_number      = "EXAMPLE123"
  enrolled_device_id = 42
  name               = "Example's iPad"
  timeout_seconds    = 120
}
```

## Schema

### Required

- `enrolled_device_id` (Number) Exact active Zentral enrollment ID. Re-enrollment requires updating this identity.
- `name` (String) Desired device name. Stored in state; protect state as personal data.
- `serial_number` (String) Exact device serial number, used to guard the enrollment ID.

### Optional

- `timeout_seconds` (Number) Maximum apply wait for both commands, in seconds. Offline devices may time out with commands still queued.

### Read-Only

- `command_id` (String) Last rename command UUID, retained for recovery.
- `command_name` (String) Name targeted by the retained command. Stored to resume interrupted updates without blindly replaying a rename.
- `id` (String) The base64url-encoded serial number and enrollment ID, separated by a slash.
- `verification_command_id` (String) Last DeviceInformation verification UUID, retained for recovery.

## Import

Import using unpadded base64url(serial_number), a slash, and the positive enrollment ID:

```shell
terraform import zentral_mdm_device_name.device RVhBTVBMRTEyMw/42
```

The same ID works with `tofu import`. Import reads the current inventory name and sends no command. Match the configuration name to that observation to adopt it unchanged.
